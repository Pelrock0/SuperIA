¿Qué es Sofia4Devs?

Sofia4Devs es un sistema de agentes especializados para Cursor que orquesta el desarrollo de features siguiendo un workflow estructurado. Define QUIÉN actúa (agentes), CÓMO se hace el trabajo (skills), QUÉ se produce (artefactos) y CUÁNDO se puede avanzar (gates).

Principios Fundamentales

  • No step can be skipped – Ningún paso puede saltarse
  • No gate can be implicit – Ningún gate puede ser implícito
  • 100% test coverage – Cobertura de tests obligatoria
  • Trazabilidad completa – Todos los artefactos están versionados

Workflow de Desarrollo

Flujo por Complejidad

El workflow se adapta según la complejidad de la feature:

Complejidad PRD Tech Design Ruta
LOW No No S1 → S1b → S4 → S5 → S6
MEDIUM Sí Recomendado S1 → S2 → S3 → S4 → S5 → S6
HIGH Sí Sí S1 → S2 → S3 → S4 → S5 → S6

Avanzar al Siguiente Paso (CLI)

Cuando el usuario pida por prompt "siguiente paso", la acción es ejecutar el comando approve del CLI:

python cli/cli.py approve {FEATURE-ID}

Ejemplo: python cli/cli.py approve FEAT-2024-001. approve = siguiente paso.

Agentes del Sistema

scope-analyzer

Responsabilidad: Analizar scope y clasificar complejidad (LOW/MEDIUM/HIGH). Step: S1, S1b. Output: 01-scope.md

product-owner

Responsabilidad: Crear PRDs con objetivos, scope y acceptance criteria. Step: S2. Output: 02-prd.md

ux-designer

Responsabilidad: Artefactos UX cuando el PO lo requiere. Step: S2 (opcional).

architect

Responsabilidad: Diseños técnicos listos para implementación. Step: S3. Output: 03-technical-design.md

backend-developer

Responsabilidad: Implementar backend con 100% test coverage. Step: S4a. Output: código, tests, 04-implementation-notes.md

frontend-developer

Responsabilidad: Implementar frontend según diseño y UX. Step: S4b.

code-reviewer

Responsabilidad: Revisar código contra PRD y diseño. Step: S5.1. Output: 05-review-results.md

security-reviewer

Responsabilidad: Revisar seguridad del código. Step: S5.2.

test-gate

Responsabilidad: Validar tests vs acceptance criteria. Solo bloquea. Step: S5.3.

ui-ux-reviewer

Responsabilidad: Revisar UI/UX implementada (condicional). Step: S5.4.

Core Rules

Tech Stack Soportado

Backend: Laravel 11+ / PHP 8.3+, Node/Express/Fastify (TypeScript), Python/FastAPI/Django. Frontend: React/Next.js, Vue/Nuxt, Blade/Livewire, Django/HTMX. Database: MySQL, PostgreSQL, MongoDB.

Arquitectura (NON-NEGOTIABLE)

Hexagonal / Clean: Domain independiente del framework, controllers delgados, lógica de negocio en Services/Domain, transacciones explícitas en Service layer.

Testing (100% COVERAGE REQUIRED)

Services, Domain, Controllers, Utilities, Hooks y Components: 100% cobertura. No se permite saltarse tests.

CLI – Comandos

Comando Uso Descripción
create python cli/cli.py create {FEATURE-ID} Crea feature en estado S1
status python cli/cli.py status {FEATURE-ID} Estado actual
approve python cli/cli.py approve {FEATURE-ID} Aprobar gate y avanzar
require-s1b python cli/cli.py require-s1b {FEATURE-ID} Marcar mini-scope (LOW)
prepare python cli/cli.py prepare {FEATURE-ID} Preparar contexto para el paso actual

Artefactos y Convenciones

Feature ID: FEAT-YYYY-NNN. Ruta: docs/features/{FEATURE-ID}/ con 01-scope.md, 02-prd.md, 03-technical-design.md, 04-implementation-notes.md, 05-review-results.md.

Git: rama feature/{FEATURE-ID}-short-description, commits [{FEATURE-ID}] Description.
