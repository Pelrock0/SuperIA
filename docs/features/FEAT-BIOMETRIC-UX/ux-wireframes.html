💡 Decisión de diseño — modal no bloqueante y dismissible
El modal se puede cerrar con X / ESC / click fuera / botón "Ahora no" — todos equivalentes semánticamente a declinar. Nota al pie recuerda la alternativa manual (ajustes), para que el usuario no sienta que pierde la oportunidad. CTA primario con gradiente corporativo (mismo gradiente que LoginPage). Icono 🔐 genérico — NO logos de marcas (Apple/Microsoft) para evitar restricciones de uso de marca.

🎯 Component States — BiometricOptInModal

Idle (default)
Botones activos. Sin mensaje de error.
Loading (tras "Activar")
Botón "Activar" muestra spinner + texto "Verificando…". Botón "Ahora no" deshabilitado.
Error (fallo WebAuthn)
Mensaje inline: "No se pudo activar la biometría. Inténtalo de nuevo." Botones vuelven a estado idle.
Success
Modal se cierra. Toast breve: "Biometría activada" (3 seg).

🔀 Alternativas consideradas

Opción Pros Contras Decisión
Modal post-login tras primera sesión Momento receptivo; descubrimiento natural Puede sentirse invasivo Seleccionado
Banner persistente en dashboard No interrumpe; siempre visible Se ignora; noise en dashboard Rechazado
Prompt en registro inmediato Máxima adopción Vincula credencial a cuenta sin email verificado — riesgo seguridad Rechazado
Email de invitación post-registro No fricción en sesión activa Baja tasa de click; requiere link handling Rechazado
Tooltip/onboarding tour Educativo Complejidad implementación; usuarios saltan tours Rechazado

⚠️ UX Risks

Riesgos identificados
• Dispositivo compartido: familiar podría aceptar por error. Mitigado: el prompt nativo del SO exige biometría del titular real; copy refuerza "tu propio dispositivo".
• Modal percibido como spam: cooldown de 30 días + botón "Ahora no" visible mitigan fatiga.
• Confusión entre "Activar" y "Entrar": distinguir copy — activar = configurar; entrar = autenticar.
• Usuarios que limpian cookies: perderán el cooldown y verán el modal de nuevo. Aceptado por diseño (consecuencia de decisión per-dispositivo).
• Fallo del prompt del SO: si el usuario cancela, el mensaje de error debe ser neutro (no dar detalles técnicos) y permitir reintento sin cerrar el modal.
