Sofia4Coa Workflow

Un sistema de desarrollo asistido por IA con agentes especializados, control de calidad automatizado y trazabilidad completa de principio a fin.

❌ El Problema Tradicional

Los desafíos del desarrollo de software empresarial sin metodología estructurada

📋

Requisitos Ambiguos

Los requisitos se pierden, cambian sin control y nadie sabe exactamente qué se debe construir.

🔄

Scope Creep

"¿Puedes añadir esto también?" se convierte en un proyecto completamente diferente sin documentar.

🧪

Calidad Inconsistente

Sin revisiones obligatorias, el código de baja calidad llega a producción.

📊

Sin Trazabilidad

No hay forma de saber qué se decidió, cuándo, por qué, ni cuánto tardó.

✅ Nuestra Solución

Un sistema de 4 capas que garantiza calidad, trazabilidad y eficiencia

Arquitectura del Sistema

📜

Rules (Reglas Globales)

Reglas no negociables que aplican a TODO el proyecto: arquitectura, calidad, seguridad.

🔄

Workflow (Flujo de Trabajo)

6 pasos con gates obligatorios. Ningún paso se puede saltar. Cada gate tiene criterios explícitos.

🤖

Agents (Agentes IA)

9 roles especializados: Analista, Product Owner, Arquitecto, Developer, Reviewers...

🎯

Skills (Habilidades)

9 skills específicos que definen CÓMO cada agente ejecuta su trabajo.

⌨️

CLI (Command Line Interface)

Herramienta para gestionar el estado del workflow, aprobar gates y medir métricas.

🔄 El Workflow Completo

6 pasos con gates obligatorios - ninguno se puede saltar

STEP 1 GATE S1

Scope Analysis

Análisis de alcance y riesgos ANTES de cualquier trabajo. Clasifica en LOW / MEDIUM / HIGH. Si es LOW, puede saltar PRD.

🔍 scope-analyzer.md
STEP 2 GATE S2

PRD (Product Requirements)

Documento de requisitos completo con objetivos, alcance explícito, criterios de aceptación en Given/When/Then, y TBDs marcados.

📋 product-owner.md
STEP 3 GATE S3

Technical Design

Diseño técnico con arquitectura, boundaries de transacciones, trade-offs explícitos y alternativas rechazadas documentadas.

🏗️ architect.md
STEP 4 GATE S4

Implementation

Implementación estricta según el diseño aprobado. Tests obligatorios. Sin atajos ni rediseño sobre la marcha.

💻 backend-developer.md
STEP 5 GATE S5

Reviews (4 tipos)

Code Review + Security Review + Test Gate + UI/UX Review (si aplica). TODOS deben pasar para continuar.

👁️ code-reviewer.md + security-reviewer.md + test-gate.md
STEP 6 GATE S6

Done

Feature completada. Todos los gates pasados. Lista para merge y deployment.

✅ Métricas finalizadas

🤖 Los 9 Agentes IA

Cada agente tiene un rol específico y responsabilidades claras

🔍

Scope Analyzer

Analista Técnico Senior

Evalúa complejidad y riesgos ANTES de cualquier trabajo. Decide si se necesita PRD completo o basta con mini-scope.

📋

Product Owner

PO Enterprise

Escribe PRDs que son contratos claros entre negocio y tecnología. Define el QUÉ, nunca el CÓMO.

🏗️

Architect

Arquitecto de Software

Traduce requisitos en diseño técnico. Define boundaries, transacciones, trade-offs y alternativas rechazadas.

💻

Backend Developer

Desarrollador Senior

Implementa exactamente lo diseñado. Sin rediseño, sin scope creep, sin atajos. Tests obligatorios.

👁️

Code Reviewer

Revisor de Código

Valida calidad, mantenibilidad, rendimiento. No rediseña, solo verifica cumplimiento.

🔒

Security Reviewer

Especialista en Seguridad

Revisa vulnerabilidades, autenticación, autorización, manejo de datos sensibles.

🧪

Test Gate

Guardián de Tests

Bloquea si los tests no existen o son insuficientes. No sugiere mejoras, solo bloquea o pasa.

🎨

UX Designer

Diseñador de Experiencia

Define diseño de interfaces cuando el PRD lo requiere. Solo se activa si hay rediseño de UX.

✨

UI/UX Reviewer

Revisor de Interfaces

Revisa implementación de UI contra diseño aprobado. Solo aplica si la feature modifica vistas.

✨ Lo Genial de Este Sistema

Por qué esta implementación es especial

01

Gates No Negociables

Cada paso tiene un gate con criterios explícitos. No se puede saltar ninguno. Si algo falla, se vuelve al paso anterior. Esto garantiza calidad consistente.

02

Separación de Roles

Cada agente tiene responsabilidades claras y NO puede salirse de ellas. El Arquitecto no implementa. El Developer no rediseña. Esto evita conflictos y scope creep.

03

Trazabilidad Total

Cada decisión queda documentada en PRD, Design y Review. El CLI registra timestamps de cada paso. Siempre sabes quién decidió qué y cuándo.

04

Reglas > Agentes

Las reglas globales aplican siempre, sin importar qué agente esté actuando. Arquitectura limpia, tests obligatorios, código sin TODOs son leyes, no sugerencias.

05

Métricas Automáticas

Lead time, iteraciones de review, findings críticos... todo se calcula automáticamente. Datos reales para mejorar el proceso.

06

Escalabilidad por Complejidad

Features LOW pueden saltar PRD. MEDIUM/HIGH requieren documentación completa. El proceso se adapta al riesgo, no al capricho.

📋 ¿De qué iba esta feature?

Objetivo: Crear una API REST segura para que Power Automate pueda notificar a Sofia4Coa cuando llega un nuevo COA (Certificado de Análisis) desde proveedores externos.

🔐
Autenticación JWT

Power Automate se autentica con usuario/contraseña y recibe un token JWT válido por 180 minutos.

📨
Recepción de Eventos

Endpoint protegido que recibe: remitente, fecha de recepción, nombre del PDF y ubicación en SharePoint.

🛡️
Zero Side Effects

Si el JWT es inválido (401) o el payload está mal formado (400), NO se persiste nada. Cero basura en BD.

📊
Logs Técnicos

Todos los intentos (exitosos o fallidos) quedan registrados en logs técnicos separados para troubleshooting.
