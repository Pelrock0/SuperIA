Agent-Driven Development Workflow

An AI-assisted development system with specialized agents, automated quality control, and complete traceability from start to finish.

The Traditional Problem

The challenges of enterprise software development without structured methodology

Ambiguous Requirements

Requirements get lost, change without control, and nobody knows exactly what needs to be built.

Scope Creep

"Can you add this too?" becomes a completely different project without documentation.

Inconsistent Quality

Without mandatory reviews, low-quality code reaches production.

No Traceability

There's no way to know what was decided, when, why, or how long it took.

The Solution

A 4-layer system that guarantees quality, traceability, and efficiency

The Complete Workflow

6 steps with mandatory gates - none can be skipped

STEP 1 GATE S1

Scope Analysis

Scope and risk analysis BEFORE any work. Classifies as LOW / MEDIUM / HIGH. If LOW, can skip PRD.

scope-analyzer.md
STEP 2 GATE S2

PRD (Product Requirements)

Complete requirements document with objectives, explicit scope, acceptance criteria in Given/When/Then, and marked TBDs.

product-owner.md
STEP 3 GATE S3

Technical Design

Technical design with architecture, transaction boundaries, explicit trade-offs, and documented rejected alternatives.

architect.md
STEP 4 GATE S4

Implementation

Strict implementation according to approved design. Mandatory tests. No shortcuts or on-the-fly redesign.

backend-developer.md
STEP 5 GATE S5

Reviews (4 types)

Code Review + Security Review + Test Gate + UI/UX Review (if applicable). ALL must pass to continue.

code-reviewer.md + security-reviewer.md + test-gate.md
STEP 6 GATE S6

Done

Feature completed. All gates passed. Ready for merge and deployment.

Metrics finalized

The 9 AI Agents

Each agent has a specific role and clear responsibilities

🔍

Scope Analyzer

Senior Technical Analyst

Evaluates complexity and risks BEFORE any work. Decides if full PRD is needed or mini-scope is sufficient.

📋

Product Owner

Enterprise PO

Writes PRDs that are clear contracts between business and technology. Defines the WHAT, never the HOW.

🏗️

Architect

Software Architect

Translates requirements into technical design. Defines boundaries, transactions, trade-offs, and rejected alternatives.

💻

Backend Developer

Senior Developer

Implements exactly what was designed. No redesign, no scope creep, no shortcuts. Mandatory tests.

👁️

Code Reviewer

Code Reviewer

Validates quality, maintainability, performance. Does not redesign, only verifies compliance.

🔒

Security Reviewer

Security Specialist

Reviews vulnerabilities, authentication, authorization, sensitive data handling.

🧪

Test Gate

Test Guardian

Blocks if tests don't exist or are insufficient. Does not suggest improvements, only blocks or passes.

🎨

UX Designer

Experience Designer

Defines interface design when the feature includes visual components or user flows.

✨

UI/UX Reviewer

Interface Reviewer

Reviews UI implementation against approved design. Only applies if the feature modifies views.

cli.py create <feature>

Creates a new feature and starts at S1

cli.py approve <feature> <step>

Approves a gate and advances to the next

cli.py reject <feature> <step> "reason"

Rejects with documented reason

cli.py status <feature>

Shows the complete workflow state

cli.py add-time <feature> <minutes>

Records human time invested

cli.py metrics <feature>

Calculates final metrics (lead time, iterations)

What Makes This System Great

Why this implementation is special

01

Non-Negotiable Gates

Every step has a gate with explicit criteria. None can be skipped. If something fails, it returns to the previous step. This guarantees consistent quality.

02

Role Separation

Each agent has clear responsibilities and CANNOT exceed them. The Architect doesn't implement. The Developer doesn't redesign. This prevents conflicts and scope creep.

03

Complete Traceability

Every decision is documented in PRD, Design, and Review. The CLI records timestamps for each step. You always know who decided what and when.

04

Rules > Agents

Global rules always apply, regardless of which agent is acting. Clean architecture, mandatory tests, code without TODOs are laws, not suggestions.

05

Automatic Metrics

Lead time, review iterations, critical findings... everything is calculated automatically. Real data to improve the process.

06

Complexity-Based Scaling

LOW features can skip PRD. MEDIUM/HIGH require complete documentation. The process adapts to risk, not whim.

What was this feature about?

Objective: Create a secure REST API so that Power Automate can notify Sofia4Coa when a new COA (Certificate of Analysis) arrives from external suppliers.

JWT Authentication

Power Automate authenticates with username/password and receives a JWT token valid for 180 minutes.

Event Reception

Protected endpoint that receives: sender, reception date, PDF name, and SharePoint location.

Zero Side Effects

If JWT is invalid (401) or payload is malformed (400), NOTHING is persisted. Zero garbage in DB.

Technical Logs

All attempts (successful or failed) are recorded in separate technical logs for troubleshooting.
