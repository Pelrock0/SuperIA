Technical documentation for the AI-powered development workflow system.

📘 About This Document

This document covers the technical implementation of the Sofia4Coa AI workflow system, including architecture, agents, skills, CLI tools, and integration with Cursor IDE.

Key Principles

  • Rules > Agents: Global rules always take precedence over agent behavior
  • Gates are mandatory: No step can be skipped, no gate can be implicit
  • Separation of concerns: Each agent has clear responsibilities and cannot exceed them
  • Full traceability: Every decision is timestamped and stored in state files

CLI Overview

The CLI (cli.py) is a Python script that manages feature workflow state.

Location

cli/cli.py

Dependencies

  • Python 3.x (standard library only)
  • No external packages required

State Storage

cli/state/{feature-name}.json

CLI Commands

create — Create new feature

$ python cli/cli.py create my-feature
Feature 'my-feature' created (S1)

approve — Approve current gate and advance

$ python cli/cli.py approve my-feature S1
S1 approved. Current step: S2

reject — Reject with documented reason

$ python cli/cli.py reject my-feature S5 "Missing security tests"
S5 rejected: Missing security tests

status — Show full feature state

$ python cli/cli.py status my-feature
{ "feature": "my-feature", "status": "S4", "workflow": { ... } }

add-time — Register human time spent

$ python cli/cli.py add-time my-feature 15
Added 15 minutes to feature 'my-feature'

metrics — Calculate final metrics

$ python cli/cli.py metrics my-feature
{ "lead_time_minutes": 45, "review_iterations": 0, "critical_findings": 0, "human_time_minutes": 25 }

State Management

Each feature has a JSON state file that tracks its entire lifecycle.

State File Schema

{ "feature": "s4c-coa-events-api", "created_at": "2026-01-02T16:24:23.899127+00:00", "status": "S6", "require_s1b": false, "workflow": { "S1": { "entered_at": "2026-01-02T16:24:23.899137+00:00", "approved_at": "2026-01-02T16:25:56.391335+00:00" }, "S2": { ... }, "S3": { ... }, "S4": { ... }, "S5": { ... }, "S6": { ... } }, "metrics": { "review_iterations": 0, "critical_findings": 0, "human_time_minutes": 25 }, "lifecycle": { "discarded": false } }

State Transitions

# Valid transitions
S1 → S2  # After scope approval (MEDIUM/HIGH)
S1 → S1b # After scope approval (LOW)
S1b → S4 # Mini-scope approved, skip to implementation
S2 → S3  # PRD approved
S3 → S4  # Design approved
S4 → S5  # Implementation complete
S5 → S4  # Review failed (loop back)
S5 → S6  # All reviews passed

State Machine Implementation

The CLI implements a simple state machine with the following logic:

def approve(feature, step):
    data = load_feature(feature)
    current = data["status"]
    
    if current != step:
        raise Error(f"Cannot approve {step} while in {current}")
    
    data["workflow"][step]["approved_at"] = now()
    
    # State transition logic
    next_step = {
        "S1": "S2",
        "S2": "S3",
        "S3": "S4",
        "S4": "S5",
        "S5": "S6",
    }.get(step)
    
    data["status"] = next_step
    data["workflow"][next_step] = {
        "entered_at": now()
    }
    
    save_feature(feature, data)

Metrics System

The system automatically tracks and calculates development metrics.

Tracked Metrics

Metric Description Calculation
lead_time_minutes Time from PRD approval to completion S6.approved_at - S2.approved_at
review_iterations Number of review rejections Incremented on each reject call
critical_findings Number of critical issues found Incremented on each reject call
human_time_minutes Human time spent (approvals, decisions) Manually added via add-time

Metrics Calculation

def metrics(feature):
    data = load_feature(feature)
    wf = data["workflow"]
    
    start = parse_ts(wf["S2"]["approved_at"])
    end = parse_ts(wf["S6"]["approved_at"])
    
    lead_time = (end - start).total_seconds() / 60
    
    return {
        "lead_time_minutes": lead_time,
        "review_iterations": data["metrics"]["review_iterations"],
        "critical_findings": data["metrics"]["critical_findings"],
        "human_time_minutes": data["metrics"]["human_time_minutes"]
    }

Cursor Integration

The system integrates with Cursor IDE through the .cursor/ directory.

How It Works

  1. Cursor reads .cursor/rules.md as global context
  2. When prompted with a step (e.g., "Execute S1"), Cursor:
    • Loads the appropriate agent definition
    • Applies the corresponding skill
    • Follows the workflow constraints
  3. Human approves via CLI: cli.py approve feature step
  4. State advances to next step

Prompt Format

# Typical prompt to execute a workflow step

# === GLOBAL RULES ===
# (automatically included by Cursor)

# === CONTEXT ===
Feature: my-feature
Step: S1
Task: Execute this step. Follow rules strictly.
✅ Key Benefits
  • Consistency: Same process for every feature
  • Traceability: Every decision is timestamped
  • Quality: Mandatory gates prevent shortcuts
  • Metrics: Automatic tracking for continuous improvement
